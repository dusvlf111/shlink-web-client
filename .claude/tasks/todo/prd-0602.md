## 0. 공통 배경 (아키텍처)

이 프로젝트는 표준 `shlink-web-client` 포크로, 다음이 커스터마이즈되어 있습니다.

- **서버 목록 / 인증은 PocketBase가 단일 진실원본(SoT)**입니다.
  - 인증·역할: `src/lib/pocketbase.ts` (`role: admin | member`, `status`)
  - 서버 목록: PocketBase `server_configs` 컬렉션 → `src/servers/services/serverConfigsService.ts`
  - 앱 부팅 시 `fetchServers` 썽크가 PocketBase를 읽어 `replaceServers()`로 **Redux 서버 목록 전체를 교체**합니다. (`src/servers/reducers/remoteServers.ts:38-58`)
- **단축 링크/방문 통계/도메인 관리 화면은 외부 패키지** `@shlinkio/shlink-web-component`가 렌더링합니다. (`src/common/ShlinkWebComponentContainer.tsx`, 라우트 catch-all `src/app/App.tsx`의 `/server/:serverId/*`)
- 이 외부 패키지는 영어 전용이라, **빌드 타임 문자열 치환 패치**로 한글화합니다. (`scripts/patch-shlink-i18n.mjs`, `postinstall`에서 자동 실행)
- UTM 도구(빌더/벌크/템플릿/태그)는 이 포크가 직접 만든 기능이며 PocketBase 컬렉션(`utm_templates`, `utm_tags`)에 저장합니다. (`src/utm/*`)

우선순위 표기: **P0**(데이터 신뢰성/핵심 동작 깨짐) > **P1**(기능 개선) > **P2**(편의).

## 1. [P0] UTM 벌크 "전체 해제" 동작 안 함 (원본 #1, #6)

### 증상
UTM 벌크 생성 페이지(`/server/:id/utm-bulk-builder`)에서 "전체 해제" 버튼을 눌러도 선택이 즉시 다시 전체 선택됨.

### 근본 원인 (확인됨)
`src/utm/UtmBulkBuilderPage.tsx:159-165`의 자동 선택 effect:
```ts
useEffect(() => {
  if (templates.length === 0 || selectedIds.length > 0) {
    return;
  }
  setSelectedIds(templates.map((t) => t.id));
}, [templates, selectedIds.length]);   // ← selectedIds.length 가 의존성
```
- 의도: 템플릿이 처음 로드될 때 한 번 전체 선택.
- 버그: 의존성에 `selectedIds.length`가 있어, 사용자가 `toggleAll`(`:187-189`)로 `selectedIds`를 `[]`로 만드는 순간 effect가 재실행 → `length === 0`이라 가드를 통과 → **전체 재선택**. 무한 재선택 루프.

### 해결 방향
- 최초 1회 부트스트랩만 수행하도록 변경. 예: `selectedIds.length`를 의존성에서 제거하고 `templates`가 0→N으로 처음 채워질 때만 초기화하는 ref 가드 사용. (사용자가 의도적으로 비운 상태와 "아직 초기화 안 됨"을 구분)

### 인수 조건
- "전체 해제" 클릭 시 0개 선택 상태가 유지된다.
- "전체 선택"은 정상 동작한다.
- 개별 체크 토글(`toggleSelected`)은 영향 없다.
- 페이지 첫 진입 시 기존처럼 전체 선택된 상태로 시작한다(원래 UX 유지).

## 2. [P0] UTM 템플릿 "수정→저장 미적용" + 공유 권한 정책 (원본 #4)

### 증상 (정정·확정)
> ⚠️ 최초 메모의 "삭제 안 됨"은 사용자 정정으로 **"UTM 템플릿 관리에서 수정 후 저장이 적용되지 않음"**이 정확한 증상임. 삭제/수정/생성 전반의 공유 권한 문제와 함께 다룬다.

UTM 템플릿 관리(`/server/:id/utm-template-manager`)에서 기존 템플릿을 "수정"으로 불러와 값을 바꾸고 "템플릿 수정 저장"을 눌러도 **변경이 반영되지 않음**. 화면상 성공/실패 안내도 없음(무반응 체감).

### 실측 데이터 (PocketBase, 라이브 — superuser로 확정)
- `utm_templates` 35개 = **2명 소유**(현재 admin 8개 / `s1u9hmm3kze37ls` 27개), `utm_tags` 5개 = **3명 소유**. orphan(빈 user) 0.
- **라이브 룰 = repo `schema.json`과 100% 동일, 전부 permissive**:
  - `utm_templates`·`utm_tags`: `list/view/create/update/delete` 모두 `"@request.auth.id != ''"`.
- ✅ **결론: PocketBase 권한은 수정/삭제를 막고 있지 않다.** 로그인한 누구나 이미 남의 레코드도 수정·삭제 가능 → **DB 룰 변경 불필요**. 사용자 정책("누구나 생성·수정·삭제")은 DB 레벨에서 **이미 충족**.
- ❌ (정정) 이전 PRD의 "라이브 룰이 소유자 제한일 것"이라는 추정은 superuser 실측으로 **반증됨**. → 버그는 **순수 클라이언트 코드 문제**.

### 근본 원인 (클라이언트로 재확정)
1. **에러가 전혀 표면화되지 않음 (주범)** — `updateTemplate`/`updateTag`(`useUtmData.ts:152-168`, `:92-105`)에 `try/catch` 없음. `handleSave`(`UtmTemplateManager.tsx:62-64`)는 `await updateTemplate(...)` 직후 무조건 "수정됐습니다"를 띄우는 구조 → 내부에서 throw가 나면 성공 메시지·폼 리셋이 안 되고 **에러도 안 보임** → "저장이 안 됨"으로 체감. 실제 throw 원인(네트워크/직렬화/SDK autocancel 등)이 가려져 있음. *실행 단계에서 try/catch를 넣는 순간 진짜 원인이 드러남.*
2. **빈 optional 필드가 update에서 누락됨** — `normalizeTemplate`(`useUtmData.ts:36-44`)이 빈 `campaign/term/content`를 `undefined`로 변환. `pb.update(id, {...})`는 JSON 직렬화 시 `undefined` 키를 **드롭** → 값을 비워도 PocketBase에 반영되지 않음(옛 값 유지). "수정이 적용 안 됨"의 한 갈래. (값 비우기는 `""`/`null`로 보내야 함)
3. **수정 시 소유자 덮어씀** — `updateTemplate`이 페이로드에 `user: userId`(현재 유저)를 포함(`:163-166`). 룰이 permissive라 403은 안 나지만, **편집할 때마다 소유권이 편집자로 바뀌는 부작용**. 공유 자원에선 원 소유자 보존이 맞음.
4. (삭제도 동일 구조) `deleteTemplate`(`:170-173`)·`deleteTag`(`:87-90`) 에러 처리 없음, 호출부 `void deleteX()`(`UtmTemplateManager.tsx:347`, `UtmTagManager.tsx:178`)로 reject 무시.

### 결정된 해결 (사용자 정책: 누구나 생성·수정·삭제 — DB는 이미 충족)
1. **DB 룰: 변경 없음** (이미 permissive, schema.json과 일치 — superuser 실측 완료).
2. **에러 표면화 + 정직한 성공 표시**: `update*/delete*`에 `try/catch` 추가, 실패 시 원인 메시지 노출. `handleSave`는 **실제 resolve 후에만** 성공 메시지. 호출부도 `await`로 결과 확인 → 동시에 #1의 숨은 throw 원인이 드러남.
3. **빈 optional 필드 처리**: update 시 `undefined` 대신 `""`(또는 `null`)을 보내 비우기가 반영되게.
4. **수정 시 소유권 보존**: update 페이로드에서 `user` 재할당 제거.

### 인수 조건
- 로그인한 어떤 유저든(소유자 아니어도) 템플릿/태그를 생성·수정·삭제할 수 있다. *(DB 룰상 이미 가능 — 회귀 없도록 보장)*
- 남이 만든 템플릿을 수정·저장하면 변경이 즉시 반영된다(필수·선택 필드 모두, 비우기 포함).
- 수정으로 인해 소유자(`user`)가 편집자로 바뀌지 않는다.
- 저장/삭제 실패 시 원인이 보이는 에러 메시지가 표시되고, 성공 메시지는 실제 성공 후에만 뜬다.

## 3. [P0] 방문 수 비정상 부풀림 — 봇/해외 트래픽 (원본 #2)

### 증상 (확정)
방문 수가 **비정상적으로 부풀려져** 집계됨. 봇/해외 트래픽이 통계에 그대로 잡히는 것이 원인으로 추정. (배너·스토리 링크는 정상적으로 사용 중이었음)

### 결정된 방향 (사용자 확인)
**두 가지를 함께 적용**한다:

#### 3-A. [클라이언트] 봇 방문 기본 제외
- `@shlinkio/shlink-web-component`는 `excludeBots` 옵션을 이미 지원함(번들 내 50+ 참조 확인). 방문 데이터에 `potentialBot` 플래그가 들어옴.
- **설정의 "방문(Visits)" 섹션에서 "가능한 한 봇 제외"를 기본 ON**으로 만든다.
  - 점검 위치: 클라이언트가 web-component에 넘기는 settings 초기값(visits settings). `src/settings`/Settings 컨테이너에서 `defaultBotsVisits`(또는 동등 키) 기본값 설정.
- 참고: 이 옵션 효과는 Shlink 서버 버전에 따라 달라질 수 있음(현재 서버 v5.0.2).

#### 3-B. [서버 운영 — 이 레포 밖] 해외 트래픽 수집 단계 차단
- Shlink가 **한국 외 트래픽을 애초에 방문으로 기록하지 않도록** 서버단에서 차단.
- 구현 후보(운영 작업, 이 클라이언트 레포 변경 아님):
  - 리버스 프록시(예: Coolify/Traefik/Nginx) 단에서 GeoIP 기반으로 비-KR 요청 차단 또는 리다이렉트.
  - 또는 Shlink의 방문 기록 비활성화 옵션/봇 무시 설정 조합.
- **별도 운영 태스크로 분리**하며, 본 PRD에서는 요구사항만 명시한다.

### 인수 조건
- (클라이언트) 통계 화면 진입 시 봇 추정 방문이 기본적으로 제외되어 표시된다.
- (클라이언트) 사용자가 원하면 봇 포함 보기로 토글할 수 있다.
- (서버) 한국 외 트래픽이 신규 방문으로 기록되지 않는다. *(운영 태스크 완료 기준)*
- 부풀림이 사라져 실제 사용자 방문 수에 근접한다.

> ⚠️ 한계: Shlink에는 "특정 국가만 보기" 내장 표시 필터가 없음. 따라서 국가 기준은 **수집 단계(3-B)**에서 처리하고, 표시 단계는 봇 제외(3-A)로 처리한다.

## 4. [P0] 서버 추가 시 PocketBase와 충돌 — 메뉴 진입 불가 (원본 #3)

### 증상
새 Shlink 서버를 UI로 추가하면 도메인 관리 등 다른 메뉴로 진입이 안 됨.

### 근본 원인 (확인됨)
`src/servers/CreateServer.tsx:47-64`의 이중 경로 저장:
1. PocketBase 로그인 시 `createServerConfig()`로 PocketBase에 저장(여기 성공하면 PocketBase id 사용).
2. 실패/비로그인 시 로컬 `ensureUniqueIds()`로 **이름+URL 기반 로컬 id** 생성 후 Redux에만 저장.

문제: 로컬 경로로 만든 서버는 **PocketBase에 없으므로**, 다음 부팅/동기화 때 `fetchServers` → `replaceServers()`가 Redux 전체를 PocketBase 목록으로 교체하면서 **로컬 서버가 사라짐**. 사용자가 `/server/<로컬id>/...`에 있으면 `selectServer`가 `servers[serverId]` 미스(undefined) → `serverNotFound` → `manage-domains` 등 `requiresServer` 메뉴 진입 불가. (`remoteServers.ts:45`, `selectedServer.ts:46`, `UnifiedSidebar.tsx`의 `requiresServer`)

### 결정된 방향 (사용자 확인): 로컬 생성 막고 PocketBase 동기화로 일원화
- 서버 생성은 **PocketBase 저장 성공을 보장**하고, 그 결과(PocketBase id)만 Redux에 반영.
- PocketBase 저장 **실패 시 로컬 임시 서버를 만들지 말고 명확한 에러를 노출**(현재의 silent fallback 제거).
- 결과적으로 Redux의 서버 id와 PocketBase id가 항상 일치 → `replaceServers()` 동기화 후에도 유실/미스 없음.
- (구현 메모) `CreateServer.tsx:47-64`의 fallback `ensureUniqueIds` 경로 제거 또는 비로그인/실패 시 차단 + 에러 메시지.

### 인수 조건
- 서버 추가 후 새로고침해도 서버가 유지된다.
- 서버 추가 직후 및 재진입 후 도메인 관리 등 모든 메뉴가 정상 진입된다.
- PocketBase 저장 실패 시 로컬 임시 서버가 생기지 않고 에러가 표시된다.
- 서버 추가는 admin만 가능(기존 `AdminOnlyRoute` 유지).

### 인수 조건

|------|--------|------------------|------|
| **UTM 빌더** | `utm-builder` | "여러 링크에 같은 UTM 한 벌을 붙여 한 번에 생성" | **N개 URL × UTM 1세트** |
| **UTM 벌크 생성** | `utm-bulk-builder` | "한 링크에 저장된 여러 템플릿을 한 번에 적용" | 1개 URL × N개 템플릿 |

- UTM 빌더 내부의 다중 입력 토글 명칭: **"단일 링크" / "다중 링크"** (기본은 기존과 동일한 단일 링크).
- 다중 링크 입력 영역 라벨: **"기본 URL (여러 개는 줄바꿈으로 구분)"**.

### 해결 방향
- 입력을 **줄바꿈 구분 다중 입력**(textarea)으로 확장. "단일/다중 링크" 토글로 기존 단일 input과 전환.
- `baseUrl: string` → 파싱 단계 추가(`baseUrls: string[]`). 줄 단위 split + trim + 빈 줄 제거, 각 URL 개별 검증.
- `buildUtmUrl`을 URL 배열로 매핑해 결과 목록 생성, 출력/복사/단축 생성 핸들러를 루프 처리.

### 인수 조건
- "다중 링크" 모드에서 여러 URL 입력 시 각각에 동일 UTM이 적용된 결과가 목록으로 생성된다.
- 유효하지 않은 URL은 건너뛰고 그 사실이 표시된다.
- 결과 일괄 복사 / 일괄 단축 URL 생성이 가능하다.
- "단일 링크" 모드(기본)는 기존 동작과 100% 동일하다(회귀 없음).
- 빌더/벌크 두 화면에 역할 구분 부제가 노출된다.

## 7. [P1] 한글화 — 설정 > 방문(Visits) 섹션 미번역 (신규 요청)

### 증상
상단 헤더 → 설정 → 방문 섹션에 영어 문자열이 남아 있음. (web-component 영어 잔존)

### 대상 문자열 (확인됨, `node_modules/@shlinkio/shlink-web-component/dist`)
- `"Exclude bots wherever possible (this option's effect might depend on Shlink server's version)."`
  → 예: "가능한 한 봇 제외 (이 옵션의 효과는 Shlink 서버 버전에 따라 다를 수 있습니다)."
- "봇으로 추정되는 방문 포함" 토글 라벨(부분 영어) → "봇으로 추정되는 방문 포함"
- "이전 기간과 방문 비교" → "이전 기간과 방문 비교"
- `"...won't be loaded by default."` → "방문 데이터 로드 시 이전 기간은 기본적으로 로드되지 않습니다."

### 해결 방향
- `scripts/patch-shlink-i18n.mjs`의 `REPLACEMENTS` 배열에 해당 영어 리터럴 → 한글 매핑 추가.
- ⚠️ **주의**: 일부 문자열은 JSX children으로 **쪼개져** 있음(예: `" be loaded by default."` 단편). 단순 리터럴 치환이 어려운 조각은 번들에서 정확한 분할 리터럴을 찾아 각각 매핑하거나, 문장 구조에 맞춰 분할 치환해야 함.
- 패치는 멱등(idempotent)해야 하며 `postinstall`에서 자동 적용됨.

### 인수 조건
- 설정 > 방문 섹션의 위 문자열이 모두 한글로 표시된다.
- `npm install`/`npm run build` 후에도 한글이 유지된다(패치 멱등).
- 쪼개진 문장이 어색하게 합쳐지거나 영어가 잔존하지 않는다.
